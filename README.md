```python
from tiktokforge import WebClient, TikTokSigner

with WebClient() as c:
    c.get("/api/challenge/detail/", params={"challengeName": "fyp"}).json()

TikTokSigner.generate_headers(params="aid=1233&device_id=7171234567890123456")
```

## Why this exists

Signatures rot. Every app release re-rolls the identity, every web build re-rolls
the bundle, and half the packages on this shelf are a frozen copy of a table
someone scraped in 2023. They keep returning strings. The strings stop working.

So the split is simple:

- **Web**: `X-Bogus` is generated by **TikTok's own bundle**, running. Not ported,
  not approximated. We ship `webmssdk.js`, boot it in a browser shim, and call
  the entry point the site calls. When TikTok rotates it, one script fetches the
  new one and proves it before swapping.
- **App**: `x-argus`, `x-gorgon`, `x-ladon` are arithmetic, so they live in
  Python — but the identity they are keyed with (`version_name`, `version_code`,
  `sdk_ver`, device profile) sits in one config file, not scattered through
  crypto code.

Design rules, because they came from things breaking:

1. **If it isn't running their code, it isn't a signature.** A 28-char string
   that *looks* right and 403s is worse than no library at all — you build a
   whole pipeline on top of it before you notice.
2. **No invented headers.** If the bundle doesn't emit `X-Gnarly`, we don't emit
   `X-Gnarly`. Fabricated fields are how you get flagged faster than sending
   nothing.
3. **Version identity is config, not code.** Bumping to a new app build should be
   editing a dataclass, not reading a diff of someone's crypto.
4. **Prove it, then ship it.** The updater downloads a candidate bundle, boots it,
   signs a real URL, prints the result, and only then replaces the file.
5. **Fuck is what you get when you reimplement a rotating cipher from a blog
   post.** Read the constant tables once in your life and stop guessing where
   the salt goes.
6. **Docs lie, tests don't.** 40 of them, and `tiktokforge-verify` hits the real
   edge so you can see a `200` instead of trusting a changelog.

## Install

```bash
pip install tiktok-forge
```

Web signing needs a JavaScript runtime:

| Requirement | Why |
|---|---|
| Python 3.10+ | dataclasses, typing |
| Node 16+ | executes the vendored web bundle |
| `pycryptodome`, `requests` | installed automatically |

The bridge resolves node from `TIKTOKFORGE_NODE`, then `PATH`, then the usual
install locations, and raises `NodeUnavailable` listing every path it tried if
none exist. **App signing needs no node at all.**

From source:

```bash
git clone https://github.com/6x-u/tiktok-forge
cd tiktok-forge
pip install -e ".[dev]"
```

## Web

`WebClient` is a `requests` session that signs every call fresh, merges the
standard `aid=1988` parameter set, and retries when the edge answers `200` with
an empty body (that's how a stale signature looks from the outside).

```python
from tiktokforge import WebClient

with WebClient(retries=2, timeout=25) as client:
    r = client.get("/api/challenge/detail/", params={"challengeName": "fyp"})
    data = r.json()
```

Lower level, when you already own the request:

```python
from tiktokforge import sign_web, with_signature, generate_web_headers

sign_web("https://www.tiktok.com/api/post/item_list/?aid=1988&count=20")
# {'X-Bogus': 'WMu77aEMZKcMsdoF'}

with_signature("https://www.tiktok.com/api/post/item_list/?aid=1988")
# '...&X-Bogus=WMu77aEMZKcMsdoF'

generate_web_headers("https://www.tiktok.com/api/challenge/detail/?aid=1988")
# User-Agent, Referer, X-Bogus, Cookie(msToken + tt_webid + s_v_web_id)
```

One long-lived engine, if you're signing in a loop:

```python
from tiktokforge import get_bridge

engine = get_bridge()          # one boot
engine.sign("https://www.tiktok.com/api/post/item_list/?aid=1988")
engine.info()                  # {'bundle': 'webmssdk.js', 'aid': 1988, ...}
engine.close()
```

Measured on this machine: **100 signatures in 108 ms — 1.08 ms each** after the
one-time boot. For comparison, spawning node per signature costs ~250 ms.

### What the web layer produces

| Value | Where it comes from |
|---|---|
| `X-Bogus` | vendored bundle, 16 chars, time-seeded |
| `msToken` | 107-char urlsafe base64 |
| `ttwid` | `ttwid.bytedance.com/ttwid/union/register/` |
| `verifyFp` / `s_v_web_id` | device fingerprint |
| `tt_webid` / `webId` | 19-digit id |

No `X-Gnarly`. The current bundle has no such output — see rule 2.

### Keeping the web side current

```bash
python tools/update_bundle.py --check    # report what the site serves now
python tools/update_bundle.py            # download, verify, install
```

```
current on site: 1.0.0.417  (https://sf16-.../webmssdk/1.0.0.417/webmssdk.js)
installed 1.0.0.417 (243702 bytes) - verification signature Rsmze94gXDcGo8aG
```

The previous file is kept next to it as `webmssdk.<version>.js.bak`, and
`tiktokforge/js/bundle_meta.json` records version, source URL, size and the
signature the candidate produced during verification.

## App

```python
from tiktokforge import TikTokSigner

params = (
    "aid=1233&app_name=musical_ly&device_platform=android"
    "&device_id=7171234567890123456&version_name=47.5.3&os_version=15"
)
headers = TikTokSigner.generate_headers(params=params, data="username=demo")

# x-ss-req-ticket  1792999057846
# x-ss-stub        E362BFE1DFE643B2706A8F14CDF75987   (md5 of the gzipped body)
# x-tt-trace-id    00-638557d83c17bac07f04d1-638557d83c17bac0-01
# x-khronos        1792999057
# x-ladon          WgzRqPh9J5D7EOJnDL3Ei8Qb7TWWEqDbYqn7+PIm/eL5Jk8p
# x-gorgon         8404b4d940002585b590f59040bdfbeac413362c8d4a5530446d
# x-argus          8oG6UIFRSUY4lPpNFpc6ScD8J96w9FbK...
```

Then hand them to whatever HTTP client you already use:

```python
import requests
from tiktokforge import APP_DEFAULTS

url = f"https://api.tiktokv.com/aweme/v1/feed/?{params}"
r = requests.get(url, headers={"User-Agent": APP_DEFAULTS.user_agent(), **headers})
```

### Pinned device identity

```python
from tiktokforge import AppDefaults, DeviceProfile, TikTokSigner

profile = AppDefaults(device=DeviceProfile(
    device_id="7171234567890123456",
    install_id="7171234567890123457",
    device_type="SM-S928B",
    device_brand="samsung",
    os_version="15",
    os_api=35,
    build="AP3A.240905.015",
))
profile.user_agent()
# com.zhiliaoapp.musically/2023705030 (Linux; U; Android 15; en_US; SM-S928B; ...)

TikTokSigner.generate_headers(params=params, profile=profile)
```

The UA and the signatures are generated from the same profile, so they can't
disagree — that mismatch is a common way to get dropped.

### Bumping the app version

`tiktokforge/config.py`:

```python
APP_DEFAULTS = AppDefaults(version_name="47.5.3", sdk_ver="v05.01.03-ov-android")
```

`version_code` is derived, not typed:

```
2023 + major%10 + minor:02 + patch:02 + 0
47.5.3 -> 2023705030
```

Releases that deviate go in `VERSION_CODE_OVERRIDES`. Override per call with
`version_code=` or swap the whole identity with `TikTokSigner.configure(profile)`.

### TTEncrypt payloads

The app gzips the protobuf body and then encrypts it; the library does the same
by default, so a round-trip is honest:

```python
blob = TikTokSigner.encrypt({"device_id": "7171234567890123456", "aid": 1233})
TikTokSigner.decrypt(blob)   # -> '{"device_id":"7171234567890123456","aid":1233}'
```

`encrypt(..., compress=False)` is there for raw blobs.

## API surface

| Call | Returns |
|---|---|
| `TikTokSigner.generate_headers(params, data=..., profile=...)` | `dict` of `x-*` headers |
| `TikTokSigner.encrypt(obj)` / `.decrypt(blob)` | TTEncrypt round-trip |
| `sign_web(url)` | `{'X-Bogus': ...}` |
| `with_signature(url)` | URL with `X-Bogus` appended |
| `generate_web_headers(url)` | full header set with cookies |
| `WebClient().get/post(...)` | signed `requests` response |
| `generate_ms_token()` / `generate_verify_fp()` / `generate_web_id()` | tokens |
| `get_bridge()` | long-lived signing engine |
| `version_code_for("47.5.3")` | `2023705030` |

`tiktokforge.algorithms` exposes the primitives directly — `Simon`, `SM3`,
`Argus`, `Gorgon`, `Ladon`, `TTEncrypt`, `ProtoBuf` — for when you need the
envelope without the request layer.

## Tests

```bash
pytest                  # 40 tests, no network
pytest -q --no-header
```

Covered: signature shape and rotation, `x-argus` envelope and block alignment,
Gorgon determinism and stub handling, Ladon encoding, TTEncrypt round-trip
including the random-key path, SM3 known vectors, Simon round-trip, protobuf
nested encode/decode, version-code derivation, bridge throughput.

The suite is offline on purpose. Live behaviour lives in `tiktokforge-verify`
so a network hiccup never shows up as a red test.
